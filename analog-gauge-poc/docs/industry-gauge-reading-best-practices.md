# 工业指针仪表识别最佳实践（面向本项目）

## 1) 640/448 是硬限制吗？

不是硬限制。

- 尺寸不是单一参数。至少要区分：整图表盘检测输入、裁出的表盘工作画布、指针分割模型推理输入。项目已用命名 `GaugePipelineProfile` 分开记录这些参数，不能再用一个 `segmentation_size` 同时代表裁剪和模型输入。
- Ultralytics `model.predict(... imgsz=...)` 允许覆盖输入大小；`predictor.setup_source` 会通过 `check_imgsz` 将尺寸对齐到 `stride`（默认 32）。这意味着不是模型“只能是 640”，而是当前工程选择了这一默认值。
- `check_imgsz` 与 `ultralytics` 推理文档明确：`imgsz` 可以是 `int` 或 `[h, w]`，并且会按 stride 对齐。
- ETHZ 官方源码不是把整张现场图压到 448。它先检测表盘、按检测框裁剪、保持比例补成正方形，再将表盘工作画布缩放到 `448×448`。官方注释说明该尺寸也服务于关键点网络。指针分割随后接收这张裁好的表盘图。由此可见，正确边界是“原图定位表盘，表盘 ROI 归一化”，不是“整张原图压到 640 后直接读指针”。
- 本地 checkpoint 的元数据记录 `imgsz=640`；ETHZ 官方分割调用未显式传 `imgsz`，所以有必要把“448 表盘画布”和“640 模型输入”作为独立组合验证。但 checkpoint 的训练尺寸不是业务正确性保证。不要凭直觉直接改值，应做 A/B：
  - A/B 同一批验证集 + 相同 seed 下比较识别成功率、候选率、`read_error`、失败类别（例如椭圆拟合失败/指针长度异常/角度回退）。
  - 对比指标至少包含：成功率、失败率、绝对角度偏差、`failure_reason` 分布。
- 2026-09-02 已在相同代码、模型和 CPU 环境，对 `iter1`、`iter2`、`iter2-原图` 共 17 张图、31 个通道完成三组真实图片实验：
  - 当前基线 `448→448`；
  - 官方风格拆分实验 `448 表盘画布→640 模型输入`；
  - 完整候选 `640 表盘画布→640 模型输入`。
- 两个 640 组合都没有通过回归：`448→640` 有 11 个值变化、1 个候选变化、1 个方法/说明变化和 1 个覆盖下降；`640→640` 有 11 个值变化、1 个方法/说明变化和 1 个覆盖下降。结论是不应全局切换到 `640`：
  - `iter2-原图`：`640` 没有修复同期表、JCQ 或油位计；SHM-D 由错误输出 `1` 变为未识别，属于更安全但仍未读出。
  - `iter2` 微信压缩版：`640` 将原本正确的两路 JCQ `0 mA` 改为约 `0.116/0.063 mA`，并将 SHM-D 从 `4` 改为 `1`；油位计也从约 `3.452` 漂移至 `3.514`。
  - 因此训练记录的 `640` 只能作为实验候选，不能当作正确性保证。尺寸、重采样、分割掩码和后处理存在耦合，需要逐阶段修复并保留完整回归。这是 2026-09-02 实验时的基线结论；后续完成坐标回映射、保持比例补边和全量回归后，生产默认已升级为 `448-highres-pad`，以批次运行手册为唯一当前依据。

## 2) 灰度/CLAHE/去噪/阈值/Hough/透视校正：边界与适用场景

顺序建议：
- **第一优先**：先做几何归一化（检测到表盘后先裁剪表盘候选，再做透视/椭圆校正到统一坐标系）。
- **第二优先**：在统一坐标上跑多分支增强（多版本灰度/Hough/阈值），先淘汰违反硬几何约束的候选，再对剩余候选做稳健聚类；不能使用全票通过、简单平均或普通多数投票。

核心边界：

- **灰度不是替代色彩。** 很多仪表依赖红/绿刻度环、指针高亮、阴影/反射色差，灰度会丢掉这些信息。项目里 `color_scale_reader.py` 现有方案就明确保留 HSV 分支。
- **CLAHE 不是万能增强。** `cv::createCLAHE` 只做局部对比度增强，参数（如 clipLimit、tileGridSize）选得不好会放大噪声，不是“对所有图都增益”。
- **去噪与阈值有边界。** OpenCV 的阈值族可根据噪声和照明场景选用：全局阈值、Otsu、局部自适应阈值；在高光/纹理复杂图上，适度高斯/中值去噪+形态闭运算通常更稳定。
- **Canny + Hough 是有效边缘线索。** Canny 输入为单通道图、边缘需满足阈值与抑制条件；`HoughLinesP` 是概率型线段检测，适合提取指针段落，但需配合最小线长、最大间隙参数防误检。
- **透视/椭圆矫正是关键。** `warpPerspective` 用给定变换矩阵把斜置表盘映射到统一平面；校正后再算角度是减少斜拍/旋转敏感性的关键。
- **预处理分支不是平等选民。** 同一家族的多个 CLAHE/阈值参数高度相关，不能各算一票形成虚假多数；应按方法家族归并证据，并把单个离群分支保留在 JSON 诊断中但排除出最终角度。

## 3) 为什么要“至少 5 个数字”？与“已知 metadata”如何解耦

本项目当前代码中，`robust_scale_fit` 和 `fit_label_ellipse` 都要求 OCR 数量达标才做标准拟合（`<5` 直接失败）。这是当前实现的**几何拟合稳健性策略**，不是仪表正确性的定义；一个表盘本身只印 3 个数字完全可能是正常设计。

- 这个限制并不等于“OCR 天然只会这样要求”，而是当前实现对 OCR 误检抗噪的守门设计。
- 表盘几何和刻度语义应解耦：圆/椭圆或局部弧由外框、轴心、刻度线等视觉结构拟合，不应强制依赖 5 个数字位置；OCR 只提供数值锚点和类型线索。
- 对于**未知仪表类型**：若确认是线性刻度，2 个可靠且不同的数值锚点可以定义映射，第 3 个锚点可用于验证；若无法证明线性、存在双量程或锚点互相矛盾，则只能输出候选或拒识。
- 对于**已有 metadata 的已知仪表**：可用厂家元数据作为先验（量程、刻度起止角、转向、端点捕捉规则）替代硬约束。例如端点可锁定时，2~3 个 OCR 锚点可以生成降级候选；只有同时通过几何与多分支一致性检查后，才升级为正式读数。

## 4) 几何一致性、跨尺度、拒识：避免“看起来像读数但错位”的核心实践

要点：
- **优先级调整**：先统一坐标系统（表盘裁剪+校正）后再算角度，避免不同图像尺度下的直接比较。
- **逐台表独立判断**（去掉“同量程三点一致性”）：
  1) 轴心约束：识别的是指针旋转轴心，而不是假定的图片中心。整圆轴心通常靠近圆心；半圆、1/4 圆或自定义弧的轴心可以在外接框边缘、角落甚至裁剪框之外。
  2) 指针长度约束：指针长度需在本图比例带内，不应跨过表盘外缘或过短。
  3) 有效角度弧约束：指针角度应落在元数据定义的有效刻度弧（或 OCR 推定弧）内。
  4) 方向约束：顺逆时针方向与元数据一致（若不一致，允许按 metadata 做方向翻转候选）。
- **短指针规则**：有限候选线段不必实际碰到轴心；计算候选线段所在无限直线到轴心的归一化垂距。为避免把外圈刻度线误作指针，还要同时要求候选线的径向位置、长度/宽度、颜色或分割证据合理。
- **局部圆弧规则**：拍摄角度校正后，同一数字/刻度环上的标记应与轴心保持近似相同半径；双量程、多环数字必须分别建环，不能要求所有数字到轴心距离相等。局部弧可结合轴心、刻度线的径向延长线和 RANSAC 圆/椭圆拟合恢复，不能强制完整圆可见。
- **拒识机制**：若角度约束、长度约束、椭圆残差、OCR 拟合任一不满足，返回 `not_recognized/analysis_fail` 并记录 `failure_reason`，不回退“看起来像”的近似值。
- **多尺度稳健融合**：对同一张图做 0.8x/1.0x（或 0.6x）裁剪重试，将通过硬几何约束的角度按圆周距离聚类。只有得到由至少两个不同方法家族支持的主簇，且主簇明显优于次簇时才输出；单个离群分支既不能否决主簇，也不能把主簇平均偏移。
- **无主簇就拒识**：如果两个竞争角度簇势均力敌，或只有一个未经独立方法验证的候选，返回候选/未识别，而不是为了“多数”强行选值。

## 5) 当前项目的下一步实施优先级（按你要的顺序）

1. **把“统一几何”前置**：
   - 检测到表盘后先裁剪并做透视/椭圆校正，统一到固定坐标（`RECTIFIED_SIZE` 或更一致的标准）。
   - 所有尺度/亮度/反光处理在该坐标系内进行。

2. **加入多分支与多尺度一致性投票**：
   - 分支 A：标准流程（灰度+Canny+Hough）
   - 分支 B：保留彩色（HSV/色度）
   - 分支 C：增强分支（限制 CLAHE + 滤波）
   - 先执行轴心、径向位置、长度、有效弧和方向硬约束；再按独立方法家族做角度聚类。
   - 一个少数离群分支不影响稳定主簇；没有稳定主簇时返回候选或拒识。

3. **把 `same-range` 假设改为 `per-device` 几何约束**：
   - 不再把同型号不同表设为同一读数约束；每台表独立有自己的可识别弧、中心、指针长度和方向。

4. **OCR 阶段按类型拆分**：
   - 未知线性类型：允许 2 个可靠数值锚点建立候选映射，用第 3 个锚点、刻度间距和方向做验证；无法验证则拒识；
   - 未知非线性、双量程或冲突类型：要求足够锚点或保留歧义，不用固定数字个数掩盖模型不可辨识性；
   - 有元数据类型：允许不依赖 5 个现场 OCR 数字，按已知量程/刻度规则读取，并记录几何与多分支验证证据。

5. **回归计划**：
   - 以 `iter1`、`iter2`（微信压缩版）和 `iter2-原图` 三套目录做对照评估；同一场景还要派生多分辨率/JPEG质量版本做一致性测试。保持不引入人工 observation 时 HTML/JSON 仍可复用。

## 6) 其他实践提醒（反光/阴影场景）

- 反光与过曝不能靠单一步骤“修复”。
  - 反光可遮挡局部边缘和刻度，不能只靠 CLAHE；
  - 过曝信息丢失后通常不可逆，因此应通过“几何复核+拒识”保证不出假值。
- 统一规范地把“降级到候选”和“明确拒识”写入结果，优于强行给一个数字。

## 7) 高分辨率原图与 448 表盘画布的实测边界

双分辨率的正确职责不是“所有阶段都换成原图”：

1. 完整分辨率原图只保存在临时细节路径；最长边 1920 的等比例副本负责整图表盘定位。
2. 检测框映射回高分辨率坐标后裁表盘；报告框、中心和指针再映射回定位图坐标，保持 HTML/JSON 契约稳定。
3. 非正方形补边与高分辨率来源是两个独立变量，必须用不同 profile 验证。

### 阶段图审阅

尺寸或角度问题不能只看最终箭头。使用批次命令的 `--export-processing-stages` 将实际执行路径中的原图、定位图、检测结果、裁剪、补边画布、模型输入、掩膜回映射、椭圆拟合、校正表盘和展开刻度环保存为无损 PNG。每张图必须记录真实尺寸、宽高比、来源阶段和变换，HTML 只做等比例完整缩略，原尺寸文件作为 sidecar 审阅。阶段导出是旁路诊断，不能反过来改变读数算法。

2026-09-03 的真实图片结果：

- 让指针分割直接读取高分辨率裁剪，会改变模型掩膜和指针方向，SHM-D 出现覆盖下降。
- 保留低分辨率指针分割、只把掩膜映射到高分辨率裁剪做椭圆/OCR/几何，可消除覆盖下降，但 31 个通道仍有 6 个数值漂移和 2 个诊断变化。
- 保持比例补边虽然避免几何拉伸，但会改变指针在 448 画布上的占比，原图批次成功数从 9 降到 8。
- 因此“信息更多”和“几何不拉伸”都不自动等于模型更准；输入分布、分割掩膜和后处理阈值必须一起校准。这批中间实验不能单独决定生产默认；当前已回归的默认为 `448-highres-pad`，详见批次运行手册。
