# Camera PoC Iteration 005：重做秒针候选生成

状态：`IMPLEMENTED_AWAITING_CONTINUOUS_CAMERA_RERUN`

## Observe

- 会话 `20260820-175901` 的闹钟检测率为 `54/59`，Level 1 基本成功。
- 有效读数率只有 42.4%，两秒窗口进度一致性只有 25%。
- 标注图显示程序分别指向中央汉字笔画、时针、分针和其他径向边缘。
- 相邻帧表盘中心位移中位数达到表盘半径的 6.1%，p95 为 12.3%；静态边缘因此产生明显假运动。

## Root cause

旧 Level 2 先在单帧中寻找所有中心径向线，再用短时间角速度选择秒针。中央大字产生大量合法几何候选，表盘中心抖动又使静态笔画在角度上移动。Tracker 无法从错误候选中恢复真实秒针。

## Act

1. 保留预训练 YOLO 闹钟检测，不修改 Level 1。
2. 对表盘中心和半径做时序平滑，降低逐帧圆检测抖动。
3. 用 ECC 对齐前后标准化表盘，补偿小幅平移和旋转。
4. 在对齐帧上计算“新变暗”的径向运动能量；静态汉字、时针和分针应被帧差消除。
5. 只把运动能量峰值交给秒针 Tracker，不再把所有单帧 Hough 直线作为候选。
6. 默认保存每个采样原始帧，下一轮可完整离线重放，无需反复人工拍摄。

## Verify

- 新增“粗大静态径向装饰 + 细秒针 + 整帧平移2像素”测试，旧实现缺少该能力，新实现正确把移动细针排在第一位。
- 合成完整闹钟、秒针跨12点、静态线拒绝、短时失焦保持等既有回归继续通过。
- 用会话 `20260820-175901` 的23张稀疏真实事件原图进行真实模型离线冒烟，得到少量有效序列：`14.08 → 26.25 → 27.00 → 34.75`；对应时间跨度约19.5秒，读数前进约20.7秒，运动趋势合理。
- 事件帧不连续，因此有效覆盖率不能作为最终结论；需要新程序保存的完整连续帧验证。
- 单帧真实离线处理约40～80毫秒，仍远低于500毫秒目标。
