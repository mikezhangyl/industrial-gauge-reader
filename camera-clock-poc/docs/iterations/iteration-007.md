# Camera PoC Iteration 007：把斜拍表盘还原为正视图

状态：`SUPERSEDED_BY_ITERATION_008`

> 复盘修正：这一轮只把椭圆拉回正圆，不能完整消除“近处大、远处小”的梯形透视变形。后续的 Iteration 008 改为先恢复完整透视，再用刻度和数字定向。

## 为什么要做

圆形表盘斜着面对摄像头时，画面里会变成椭圆。如果直接使用画面中的指针角度，读数会偏，而且不同指针方向的偏差不同。这个问题既影响闹钟，也影响压力表等工业仪表。

最新会话 `20260820-192012` 的表盘估计倾斜角中位数约为 `18.58°`。原报告没有开启系统时间对照，因此只能验证连续跟踪，不能证明绝对读数误差。

## 失败实验

生成一个真实秒数已知的圆形钟面，再模拟约 `52°` 的斜拍：

- 真实值：`12.50 秒`
- 修复前：`9.58 秒`
- 误差：约 `2.92 秒`

这个场景已经成为自动回归测试。

## 本轮改动

1. 在闹钟检测框里寻找表盘外圈椭圆。
2. 用椭圆长短轴比例估计表盘倾斜角。
3. 把椭圆还原为正圆，再检测秒针和计算角度。
4. 把校正后的指针位置重新映射回原图，便于人工检查。
5. 优先选择中心正确、轮廓连续、面积符合表盘的椭圆，避免在红色外壳、白色表盘和虚化边缘之间跳动。
6. 实时画面、JSONL 和 HTML 报告新增“估计倾斜角”和“是否完成正视校正”。

## 尚未证明的部分

最新旧会话没有独立真实值，不能用它证明绝对准确率。下一次实拍需要先让闹钟秒针与 Mac 系统秒数对齐，或者填写两者的固定秒数差，再使用：

```bash
python camera_poc.py --source 0 --sample-fps 2 --compare-system-time --clock-offset-seconds 0
```

## 工业项目边界

椭圆检测、倾斜估计和正视校正属于工业仪表可复用候选能力；闹钟每秒转 `6°`、秒数换算和 `50～59秒` 报警仍然只属于演示。迁入工业项目前，必须对已有工业仪表图片做回归测试。
