# Camera PoC Iteration 011：按现场画面自适应选择秒针图像通道

状态：`IMPLEMENTED_ARCHIVE_REPLAY_VERIFIED_AWAITING_LIVE_RUN`

## 本轮问题

新换的银色闹钟表面有放射状纹理和反光。表盘能够找到，但普通灰度图中的细秒针有时会被反光淹没，长期停留在“正在等待秒针运动证据”。

本轮只修改表盘找到以后的秒针图像处理和跟踪，不修改 YOLO、OCR、透视校正和隐私虚化。

## 假设与单变量实验

使用历史会话中已经检测到表盘的边框进行回放，把 YOLO 漏检隔离出去。

| 图像方式 | 银色钟有效率 | 原来的钟有效率 | 结论 |
| --- | ---: | ---: | --- |
| 普通灰度 | 71.9% | 72.6% | 原来的钟略好 |
| 局部对比度 | 78.5% | 72.1% | 银色钟明显更好 |
| 亮度归一化 | 73.3% | 70.7% | 淘汰 |
| 暗线突出 | 65.2% | 64.0% | 淘汰 |
| 两路候选直接混合 | 71.1% | 74.8% | 容易混淆不同轨迹，淘汰 |

结论：不存在一套固定处理同时赢过两种钟，应让普通灰度和局部对比度各自独立观察秒针运动，再选择证据更稳定的一路。

## 实现

1. 启动校准时，同时运行“普通灰度”和“局部对比度”两路。
2. 两路分别维护自己的秒针轨迹，不能把候选线直接混在一起。
3. 校准期间一旦已有可信读数就立即显示，不为了等待最终选择而延迟输出。
4. 积累到足够的连续运动证据后，锁定证据更强的一路；证据相同则优先普通灰度。
5. 备用通道继续低成本观察。主通道暂时被反光遮住时，备用通道可以接手，不需要重新等待完整运动证据。
6. 通道交接必须接近“上一读数按秒针速度推算的位置”。不满足时显示未知，不输出跳变读数。

这套图像通道选择属于表盘指针识别的可复用候选；“约每秒 6 度”和秒数换算仍然只属于闹钟演示。

## 回放反馈环

命令：

```bash
PYTHONPATH=src .venv/bin/python scripts/replay_pointer_sessions.py \
  sessions/20260821-124415 \
  sessions/20260821-010818 \
  --min-valid-rate 0.75
```

最终结果：

| 会话 | 时钟 | 秒针有效 | 连续性 | 大跳变 | p50 | p95 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `20260821-124415` | 银色钟 | 107/135（79.3%） | 100.0% | 0/104 | 26.5 ms | 100.0 ms |
| `20260821-010818` | 原来的钟 | 471/628（75.0%） | 99.3% | 0/447 | 26.6 ms | 143.9 ms |

这里的“有效率”只计算原会话已经找到表盘的归档帧，评价的是秒针链路，不代表整套摄像头程序的检测率。“连续性”验证秒针是否按经过的时间向前运动，不是绝对秒数真值。

## 当前判断

- 相比基线，银色钟有效率从 71.9% 提升到 79.3%。
- 原来的钟从 72.6% 提升到 75.0%，且没有明显回归跳变。
- 为消除一次通道交接造成的错误跳变，最终版本宁可暂时不报，也不会贸然接受位置不连续的备用轨迹。
- 两份历史会话回放已经通过；尚未进行这一版的真实摄像头现场运行，因此状态不能写成现场验证通过。
