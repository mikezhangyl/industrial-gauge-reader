# Camera PoC Iteration 010：修复闹钟被 COCO 标成飞盘

状态：`IMPLEMENTED_REPLAY_VERIFIED_AWAITING_LIVE_RUN`

## 根因

`19:18` 会话的闹钟检测率是 `100/103（97.1%）`，`23:57` 会话只有 `61/205（29.8%）`。模型和检测代码在 `19:00` 之前已经固定，透视、OCR 和隐私虚化又都发生在 YOLO 之后，因此不是后处理破坏了检测。

真实漏检帧里，YOLO 用 `0.883` 置信度框住闹钟，但类别是 `frisbee`。最新 `144` 张漏检帧中：

- `108` 张有 `frisbee >= 0.12`。
- `98` 张有 `frisbee >= 0.25`。
- `73` 张有 `frisbee >= 0.50`。
- `clock >= 0.12` 为 `0` 张。

根因是把 COCO 的通用语义类别 `clock` 错当成了硬门禁。

## 修复

1. YOLO 同时提取 `clock` 和 `frisbee` 候选。
2. `clock` 候选照常进入表盘精细定位。
3. `frisbee` 候选必须在校正表盘上被 PP-OCRv6 识别出至少 `3` 个钟面数字才首次确认。
4. 已验证闹钟短时被重新标为飞盘时，如果位置连续，可保持 `8` 个采样；之后必须重新验证。
5. 方法字段会记录 `COCO飞盘候选+钟面数字验证`，便于报告复盘。

## 验证

两条针对性测试已经先失败、修复后通过：

- 没有钟面数字证据的飞盘候选必须拒绝。
- 有 `8` 个数字证据的误分类候选必须接受。

真实 YOLO + 真实 PP-OCRv6 冒烟测试在原来漏检帧上成功建立 `10` 个数字参照。

| `23:57` 完整会话回放 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 检测成功 | 61/205（29.8%） | 158/205（77.1%） |
| 有效秒数 | 15/205（7.3%） | 69/205（33.7%） |
| p50 | 未单独回放 | 57.3 ms |
| p95 | 未单独回放 | 392.9 ms |
| 最大耗时 | 未单独回放 | 629.9 ms |

`19:18` 归档帧回放为 `96/103` 检测、`84/103` 有效读数，p95 `67.9 ms`，没有出现明显回归。归档帧是检测后的隐私画面，与当时模型看到的原帧不完全相同，所以不与实时 `100/103` 强行对等。

## 剩余边界

剩余 `47` 张主要是两类：

- 闹钟和手大幅快速运动，表盘和数字已经明显拖影。
- 闹钟长时间位于画面右下角之外，只剩不完整的外壳。

这些帧不应伪造精确读数。新实拍要分开评估“完整可见表盘”和“明显失焦/大面积出界”。
